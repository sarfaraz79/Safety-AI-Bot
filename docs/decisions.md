# Decisions

Newest last. Each entry: what we decided and why. Change a decision by adding a new entry, not by editing an old one.

## 30 October 2026

1. **Business shape.** Python-only stack to start; open-core model (engine Apache-2.0, hosted product paid); AWS London region; Phase 2 only after paying customers; company based in Manchester.
2. **Product name to be decided.** Code, packages and the demo company use neutral or fictional names (`demo-bot`, Example Parcels, Acme Couriers, Contoso Freight), so renaming later touches nothing important.
3. **One repo as a uv workspace.** Each package has its own dependencies and tests: the open-source engine must not pull in the demo bot's web server, and the demo bot never ships with the engine. Shared tool settings live in the root `pyproject.toml`.
4. **Model access through the official `openai` SDK, not LiteLLM.** Almost every provider (OpenAI, Claude, Gemini, Ollama) offers an OpenAI-compatible endpoint, so one well-maintained SDK plus a configurable base URL covers them with far fewer dependencies. LiteLLM's PyPI releases 1.82.7 and 1.82.8 were replaced with a credential stealer in March 2026. Revisit only if we need a provider without an OpenAI-compatible endpoint.
5. **The demo bot's flaws live in content, never code.** Real bots mostly fail after document or prompt edits, which is exactly what we sell change control for. The code stays correct and secure, so a failure we show is always a content failure.
6. **Demo bot API is stateless and observable.** Clients send the whole conversation; responses include the knowledge base sections used and the tool calls made. No session store, nothing shared between users, and tests can check actions, not just wording.
7. **Access control.** Loopback only by default. Any other host requires a bearer token of at least 16 characters, enforced at startup and on every request.
8. **In-house BM25 search for the demo bot.** A few dozen lines, no dependency, deterministic, so tests can pin the retrieval behaviour the planted flaws rely on. The engine stays retrieval-agnostic.
9. **`platform/` is renamed `hosted/`.** A top-level package called `platform` would shadow Python's standard-library `platform` module.
10. **No licence file yet.** Decide before the first public release; the plan is Apache-2.0 for the engine only.
11. **Planted flaws must be measured, and appear reliably.** A flaw needs at least 18 of 20 runs on the prompt where it should appear, and v1 must not break its rules on flaws 2 to 4. The first live test showed flaws 2 and 3 never appearing, so a demo would have shown nothing. Flaw 2's notes and the v2 prompt were reworded, and the flaw 3 email lost its "Do not mention this note" line, which made the model suspicious. Results hold for one model and wording (`demo-bot/README.md`), so the demo stays on that model and is measured again after any change.
12. **Local bot refuses other websites.** Without a token, `/chat` also checks the `Host` and `Origin` headers. Otherwise any web page open on the same machine could spend the owner's model credits. A browser-sent request can't set these headers itself.
13. **Model address must be encrypted unless local.** `DEMO_BOT_LLM_BASE_URL` must use `https` unless it is on this computer, so the API key can't cross a network unencrypted.
14. **Provider replies are validated.** The `openai` SDK doesn't enforce the shape of replies, so a gateway error page or malformed reply crashed the request. `llm.py` now checks them with Pydantic and turns anything unusable into `LLMError`, carrying only the error's type because its text can quote the reply or request.
15. **Contract format.** The engine's package is `audit-engine`, a neutral name (decision 2). Contracts are YAML because people review and edit them by hand, using `pyyaml` with safe loading only. Duplicate and merge keys are refused, because a second `approved: true` would otherwise silently overrule the first. `approved` must be a real true or false.
16. **Hidden text is never policy.** The engine's Markdown reader drops comments and front matter before anything reaches the model, because customers never see them: a draft note saying "£75" must not become a contract fact, and hidden instructions must not steer extraction. Each section costs one model call, so document size, section count and section length are all limited.
17. **Quote check is strict, and refuses to cut numbers.** A plain text search would find "capped at £50" inside "capped at £500", the exact failure we sell against, so a match can't begin or end inside a word or number. Only line breaks and repeated spaces are ignored. Formatting isn't: a quote that drops the `**` from `**£50**` is rejected and listed for the reviewer, because a false rejection costs a moment and a false pass undermines the evidence. We'll measure how often this rejects good items in the first real run.
18. **Extraction never hides a gap.** Every suggestion ends up as an item, a rejection with its reason, or part of a section reported as failed. An unusable reply gets one retry, and a provider failure stops the run, because a contract that looks complete but isn't would be worse than no contract. Sections go one at a time, which is slower, but simple and easy to keep within rate limits.
19. **The command protects approvals, and checks before spending.** `extract` won't replace an existing contract without `--force`, because that would lose a person's approvals, and it can never overwrite the policy itself. Output, settings and the document are all checked before the first model call. The engine has its own `AUDIT_ENGINE_` settings, so the auditor and the bot under test can use different models. `typer` is used as planned, with pretty exceptions off because they print local variables, including the API key.
